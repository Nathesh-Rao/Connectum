# Layout specs (JSON)
One file per screen, named like its screenshot (`NN-name.json`); the PNG sits one folder up. Generated from the live DOM at 390x844 by `../tools/run.mjs` + `../tools/extract.js` (puppeteer-core + headless Chrome; also takes the screenshots); no personal data (sample email alex@example.com).
All x/y/width/height are CSS px relative to the `.phone` frame's top-left (390x844; at this viewport the frame has no border/radius). Multiply by 2 for the PNG.
Top level: `frame`, `statusBar` (x/y/w/h, padding, 12-13px font; `null`/`visible:false` on Splash), `homeIndicator` (the 113x4 pill + `bottomAreaTop` = where the bottom home-indicator area starts), `backdrop`, `elements`, `animatedElementCount`.
`elements[]` in DOM/paint order: `kind` (text | button | input | icon | image | shape | divider), `label`, `x y width height`, `zones` (["status-bar"], ["home-indicator-area"] or both/none: which frame zone the element overlaps), `tag`, `classes`.
`style` has the computed fontFamily, fontSize, fontWeight, lineHeight, letterSpacing, color, textAlign, background (colour + gradient image, `|` separated), border (string or per-side object), borderRadius, boxShadow, padding, margin, gap, plus opacity, effectiveOpacity (product of ancestors), transform, display/flex alignment. Colors may print as `color(srgb r g b / a)` (0-1 channels) for gradient stops.
Text elements also carry `text` and `textBox` (tight box around the glyphs, `lines` = line count). Inputs carry `attrs` (type, placeholder; the typed value is never stored). Icons carry `attrs.markup` (the inline SVG paths) and the viewBox/stroke.
Onboarding art is inline SVG: the svg is a `shape`, and every circle/path/rect inside it is its own `shape` with `attrs` (cx, cy, r, d, fill, stroke...) and its on-screen bounding box.
`backdrop[]` lists the decorative shapes (ambient disc/orbit/spheres on Splash and Auth; `onb-backdrop` glow and `onb-sphere`s on Onboarding) with size, position, colour/gradient, opacity. `::before/::after` pseudo-elements (e.g. the inner orbit ring) are separate `shape` entries whose x/y are the parent's box (see `style.inset`).
`animated: true` = rect/transform/opacity changed between two samples (`animatedSample` holds both) or a CSS animation is set (`style.cssAnimation`; the Splash logo's `logo-reveal` is a one-off 0.65s fade+scale, not a loop). Onboarding spheres/art loop forever; their exact motion params are in `onboardingSphereMotion` (from source). Elements without text or visuals (pure layout wrappers) are omitted; an element's own `padding/margin/gap` still describes the wrappers' spacing. Sheet specs include the dimmed screen behind the sheet plus the `.overlay`/`.sheet-backdrop` shapes.
Added later (same format): `sampleContent: true` + `sampleKind` on text/buttons/inputs whose text is hardcoded prototype data (names, messages, amounts, dates, counts, enterprise names, form definitions); unmarked text is structural (headings, button labels, placeholders). Never treat marked text as real data.
Top-level `animations[]` (element, effect, timing, source): the authoritative motion description, using tokens from src/motion.ts (fast .19s, base .32s, slow .5s, page .45s; ease.out cubic-bezier(.25,.06,.12,1); spring 300/32; press 420/34). `scope` appears when only one element's subtree is listed (form cards, pinned summary, bottom nav). `14-bottom-nav-states.json` merges the nav in each active-tab state. Run `tools/run-more.mjs` to regenerate these.
