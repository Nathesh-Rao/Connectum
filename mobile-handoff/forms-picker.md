# Forms pills above the composer ("Test Mobile", "My Submissions")

Source: web `Composer.jsx` (Smart Prompts quick bar), `ConnectumChatScreen.jsx` (`refreshOptions`, `composerOptions`), `dedupeOptions.js`, `sd_config.erl` (`options_for`, `option_categories_for`).

- Data: `sd options.list` with **no args** returns *all* options the user may see, unpaged: `{options:[{id,caption,type,target,targetScope,owner,display,order,fromForm,fromUrl,requires?,category}]}` (server applies "applicable to", `active`, configured order). With any of `category|q|page|pageSize` it pages (`pageSize` default 20, max 100) and adds `total,totalPages,hasMore`.
- `sd options.categories {includeEmpty?}` -> `{categories:[{id,label,icon,types,executable,count}], total}`. The web uses it only for the **icon** per pill (`categoryById[o.category].icon`, fallback "bolt") and "not wired yet" (`executable:false`, Axpert options). Categories: data_input, download, upload, get_data, link, axpert (+plugin ones).
- **One pill per option** (caption = pill text, any option type, not only data_input). "Test Mobile" is an option whose `target` is the form. Options whose id has a package prefix (`hosp_`, `hr_`, `setup_`) are folded into one pill per package that opens a list. Options with `requires` are hidden unless the care-thread condition holds. Duplicates (same type|target|caption) collapse to one.
- "My Submissions" is a fixed last pill (history icon) -> opens the submissions list (`submissions.list`); "About me" appears only when `aboutMeCount > 0`. No limit in the pill bar (horizontal scroll). With no options a hint "No options for you yet" shows.
- Conversation kinds: the bar is part of the Composer, so it appears in the workspace, DMs, groups and department hosts alike (no chat-kind condition found; global room not verified). The same options are offered everywhere; picking one inside a DM/group posts the resulting form into that conversation (`chat: "dm:<u>"|"group:<g>"` on submit); in the workspace there is no `chat`.
- Mobile sheet must list: every option from `options.list` (icon by category; non-`data_input` types: `executable:false` greyed or hidden), package groups, then "My Submissions". `option.run` only for non-form types; data_input options go straight to `tstruct.get` / `tstruct.user.get` by `targetScope` (see forms-live.md).
