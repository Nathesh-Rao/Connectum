# Smart View views: questions for the BE (Task L)

Only points the code (web `origin/dev` 54a31d45699a) does not settle. Refs: `SV:` = `connectum/chat-app/features/smartView/`, `BE:` = `connectum/connectum-backend/src/`. Context: `smart-view-views-web.md`.

1. **Hidden fields on mobile.** `submissions.list` sends hidden-field values to every reader, and `tstruct.user.get` sends them with `default` to anybody who can open the form; the web lets anybody who opens a structure turn on "Show hidden fields" (`SV:SmartView.jsx:187`, test `smartViewHiddenOption.test.mjs`, dev #810). May mobile offer the same switch to everybody, restrict it (creator/admin), or will the server strip hidden values (`MOBILE_SMART_VIEW` 7.3 item 1)?
2. **Revision on saved views.** `smartview.views.save` replaces the whole list with no `rev`/`stale` (`BE:sd_svviews.erl:27-36`, `sd_cmds.erl:748`); two devices silently overwrite each other. Is a `rev` (or per-view save/remove commands) planned? Until then mobile will re-read right before each save.
3. **Per-view commands.** If no `rev`, would you add `smartview.view.save {kind,name,view}` / `smartview.view.delete {kind,name,id}` so one device cannot drop another's views?
4. **Default View in the list.** The Default View is an entry with id `__default` inside the same list (`BE:16,247`). Is it guaranteed to be unique and is its name always "Default View"? Should the server refuse another view named "Default View" (the check is client-only, `SV:SmartView.jsx:524`)?
5. **View limits.** 20 named views, 16 KB, 30 filters, 5 group levels, 300 hidden/order keys (`BE:14-15, 313-326`): are these final? Silent truncation of lists (names/filters beyond the cap are dropped without an error) is deliberate?
6. **Id format.** The web uses `Date.now()` ms as an id (`SV:SmartView.jsx:529`). May mobile use a UUID (allowed charset `[A-Za-z0-9_-]`, <= 40) or must ids stay numeric strings?
7. **Duplicate names.** A new view with an existing name silently replaces the older view (`SV:svViews.js:24`; server `dedupe` BE:264). Is that the intended product rule for mobile too, or should mobile ask first?
8. **Multi-level grouping.** `groupBy` is a list up to 5 (`BE:286`), older views a single string (`SV:svViews.js:9`). Will the web keep multi-level grouping and the "first measure column total" per group header (`SV:SmartView.jsx:268, 762`)?
9. **Hidden-field columns in saved views.** A view may list a hidden-field key in `hidden`/`order`; the column exists only while the switch is on (`SV:SmartView.jsx:182`). Is the switch ever going to be stored in a view (a key like `showHidden`)? Is "+key" (quiet column turned on) the permanent format (`SV:SmartView.jsx:539-544`)?
10. **Wrap and record heights.** Not stored in views (`SV:SmartView.jsx:277-283`). Will they be (a `rowSizes`/`wrap` key)? The server would drop unknown keys (`BE:275-297`).
11. **Shared and published views.** Sharing is hidden (`SV:svShareSwitch.js:5`); `admin.smartview.view.publish` has no UI. Should mobile show shared tabs already received, hide them, or expect a change soon? Is "Save as my own view" the only way to copy one?
12. **Inbox list views.** Docs say views of `approvals`/`reminders` stay on the device (`SV:svViews.js:3`); the code stores them on the server (`BE:65`). Which is true for mobile, and is kind `work` the right name for Tasks & tickets?
13. **Customize on mobile.** Only Cards and Charts are on in Customize (`SV:SvConfigure.jsx:17-21`); Columns and Links are switched off. Will they return? Is each person's own set-up (`smartview.attrs.save`) the intended mobile write path, or should mobile read-only the organisation default?
14. **Chart types.** 13 chart types are stored (`BE:sd_smartview.erl:39`). Which must mobile draw (the web's report maps them to donut/line/bar)? Is a fallback to bar for the rest acceptable?
15. **Export rules.** Does a download include hidden-field columns when they are shown, and the ticked rows only (`SV:SmartView.jsx:458`)? Any rule that export of hidden fields must be blocked?
16. **Rate limit on re-reads.** The web re-reads the whole table once per event (`SV:SmartView.jsx:213`; `MOBILE_SMART_VIEW` 4.5.1). May mobile debounce and re-read only the changed records, or is a "changed since" read planned?
17. **Row limit.** The web reads up to 10,000 records in pages of 500 (`SV:smartViewSources.js:77-79`). Is that the contract for mobile (memory-only rows)?
18. **Structure column order.** Our vectors still list `By`, `On`, `Status` first; current code puts the key field first, `#` internal, own fields, then quiet `With`/`Progress`, `By`, `On`, `Status` (`SV:svStructure.js:128-139`). Please regenerate `vectors.json` (the `formatCell` section was made in en-GB; the rest of the file is unchanged).
